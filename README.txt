BIDS_GATEWAY — сервис поиска заявок по выгрузкам orekeeper
==========================================================

ЧТО ДЕЛАЕТ
----------
- Читает срезы заявок, которые выгрузил orekeeper:
    <paths.bids_root>\<сессия>\months\<ГГГГ-ММ>\supply_requests.json
  Пути ОТНОСИТЕЛЬНЫЕ: ../orekeeper/data/bid — как у stock_gateway,
  сервис запускается из своей папки.
- Разворачивает все заявки в память (ArcSwap: атомарная замена каталога
  без блокировки читателей).
- Отвечает на поисковые запросы из RAM-шины (Global\KK_<очередь>_...).
- Watcher каждые N секунд проверяет новые сессии выгрузки и ГОРЯЧО
  перезагружает каталог (перезапуск сервиса не нужен).
- Отдаёт результат в очередь ответов менеджеру (bids_manager).

СТРУКТУРА ЗАЯВКИ (реальная, из supply_requests.json)
----------------------------------------------------
Файл — словарь: { "ST1": {...}, "ST2": {...} }. В каждой заявке:
  Number    — номер ("ЦЕХ_М-00546")
  Date      — дата
  Sklad     — склад / объект назначения
  Name      — название заявки
  Zakazal   — кто заказал
  Manager   — ответственный менеджер
  ZakazPodr — заказывающее подразделение (организация)
  ZakupPodr — закупающее подразделение
  Status    — статус заявки ("Выполнена", ...)
  Srochnost — срочность ("Текущая", ...)
  Details   — комментарий
  WishDate  — требуемая дата поставки
  PlanDate  — плановая дата
  CompDate  — дата исполнения (может быть ПУСТОЙ даже у выполненных заявок!)
  Tovars    — { "STT1": { StrNum, Tovar, Tovar2, Kolvo, Edizm, URL }, ... }

ДЕЙСТВИЯ (поле action в запросе)
--------------------------------
  search_bids     — поиск заявок (действие по умолчанию)
  get_bid         — полная карточка заявки по точному номеру
  get_bid_tovars  — страница товарных позиций заявки (10 позиций на страницу)

ПОИСК (поле field в запросе, действие search_bids)
--------------------------------------------------
  number  — по номеру заявки ("ЦЕХ_М-00546" -> "цех м 00546",
            ищутся и "00546", и "М-00546")
  firm    — по организации: ZakazPodr И ZakupPodr
  goods   — по товарным позициям (Tovar/Tovar2)
  name    — по названию заявки
  comment — по комментарию (Details)
  any     — по всем полям сразу (по умолчанию)

СБОРКА И ЗАПУСК
---------------
    cargo build --release
    cargo run --release
Запускать exe из папки, где лежит config.json.
Крейт `windows` НЕ нужен — шина на raw FFI (kernel32).

КОНТРАКТ ШИНЫ
------------
ВХОД (очередь создаёт Bids_Manager):
    payload.query — JSON. Три действия:

    1) Поиск заявок (как раньше):
    {
      "task_id": "...", "source": "...", "action": "search_bids",
      "params": { "keyword": "стрейч", "field": "any" }
    }
    Если пришёл не JSON — весь payload.query считается текстом запроса.

    2) Карточка заявки по номеру:
    {
      "task_id": "...", "source": "...", "action": "get_bid",
      "params": { "number": "БТ-00000157" }
    }

    3) Товарные позиции заявки (постранично, 10 на страницу):
    {
      "task_id": "...", "source": "...", "action": "get_bid_tovars",
      "params": { "number": "БТ-00000157", "page": 1 }
    }

ВЫХОД (очередь создаёт сам этот сервис):

    search_bids ->
    {
      "status": "ok", "total": 123, "truncated": true,
      "result": [ { "number": "...", "date": "...", "firm": "...",
                    "firm2": "...", "name": "...", "comment": "...",
                    "status": "Выполнена",
                    "items_count": 2, "goods_preview": "...",
                    "month": "2023-02" } ]
    }
    message_type = "bids.search.response"

    get_bid ->
    { "status": "ok",
      "result": { "number": "...", "date": "...", "name": "...",
                  "status": "Выполнена", "srochnost": "Текущая",
                  "sklad": "...", "zakazal": "...", "manager": "...",
                  "firm": "...", "firm2": "...",
                  "wish_date": "...", "plan_date": "...", "comp_date": "",
                  "comment": "...", "items_count": 117, "month": "2023-01" } }
    Если заявка не найдена: { "status": "error", "error": "Заявка '...' не найдена" }
    message_type = "bids.details.response"

    get_bid_tovars ->
    { "status": "ok", "number": "БТ-00000157",
      "total": 117, "page": 1, "pages": 12,
      "result": [ { "str_num": 1, "name": "Конфеты ...", "kolvo": "2", "edizm": "шт" }, ... ] }
    message_type = "bids.tovars.response"

    Конверт для всех ответов: source_service="Bids_Gateway",
             message_type="bids.*.response",
             task_type="reply_bids",
             correlation_id пробрасывается из запроса.

ВАЖНО ДЛЯ ОТОБРАЖЕНИЯ
---------------------
- Пустой comp_date НЕ означает, что заявка не выполнена: у статуса
  "Выполнена" дата исполнения из 1С часто не передаётся. Показывать как
  "не передана 1С".
- status может быть пустым для части заявок — показывать "Не указан".
- В товарных строках edizm может быть пустой — показывать только количество.
- name позиции = Tovar (полное название), если не пуст; иначе Tovar2.

САМОТЕСТ
--------
self_test.enabled = true — через 3 сек после старта сервис сам отправит
тестовый запрос в свою входную очередь (keyword из self_test.keyword).
В логах будет видна вся цепочка: запрос -> поиск -> публикация.
После проверки вернуть false.

ПОТОКИ
------
- 1 слушатель входной очереди (ретрай подключения, прерываемый по Ctrl+C)
- воркеры: от workers.min_threads до workers.max_threads.
  Рост: backlog >= scale_up_backlog -> новый воркер.
  Свёртывание: idle_timeout_sec простоя (не ниже min).
- watcher: периодическая проверка новых срезов.
